# Advanced Audio API protocol matrix

The matrix is organized by protocol primitive rather than provider. Every
network-facing test cited below uses a local TCP fake (HTTP, SSE, WebSocket, or
WebDAV); none calls a real ASR provider.

`Covered` means the cited tests directly assert the behavior in that row.
`Partial` means a relevant path is tested, but the stated boundary or all
listed modes are not exercised. This is a test-coverage audit, not a claim of
provider interoperability.

## Dynamic signer vectors

Section 75 is covered by fixed, deterministic unit vectors; they do not send
network requests. The AWS vector asserts the canonical request, string to
sign, session-token handling, signature inside the Authorization header, and
the header itself. The Tencent vector asserts the canonical request,
credential scope, string to sign, signature inside Authorization, and the
header.

| Signer | Coverage | Test |
| --- | --- | --- |
| AWS SigV4 | Covered | `crates/dictate-core/src/advanced_audio/auth/aws_sigv4.rs::tests::signs_aws_sigv4_fixed_vector_with_session_token` |
| Tencent TC3 | Covered | `crates/dictate-core/src/advanced_audio/auth/tencent_tc3.rs::tests::signs_tc3_fixed_vector` |

Unsupported transports or signer types fail validation before a request is
sent.
