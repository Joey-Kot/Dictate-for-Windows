# 快捷键录入验证

以下验证结果保留自更名前的记录；命令中的包名已同步为当前的 `dictate-*`，不表示本次重新执行。

## 自动验证

核心录入测试覆盖允许按键与全部修饰键组合的配置往返、符号键和小键盘映射、禁止键污染整个组合、纯修饰键、多普通键、长按重复、不同松键顺序、进入焦点时的残留按键及放弃未完成候选。

```bash
cargo fmt --all --check
cargo test --workspace --features dictate-gui/native-gui
cargo clippy --workspace --all-targets --features dictate-gui/native-gui -- -D warnings
cargo clippy --target x86_64-pc-windows-gnu -p dictate-gui --features native-gui -- -D warnings
```

以上检查在 Linux 环境运行；Windows 目标另完成了启用 `native-gui,static-libav` 的 GUI 编译和链接。自动测试不代表 Windows 键盘钩子、实际焦点或绘制效果已经实测。

## Windows 人工验收（待执行）

分别在 `HOTKEY_HOOK=true` 和 `false` 下执行：

1. 在三个输入框分别录入 `F1`、`Ctrl + Alt + S`、`Alt + Esc`；实时预览，全部松开后确认；录入期间不开始录音、不暂停、不取消、不切换窗口。
2. 验证单字母、数字、空格、符号、`Shift + =`、小键盘数字及运算键；保存并重启后触发对应动作。
3. 遍历 README 列出的禁止键，并搭配 Ctrl/Shift/Alt；原值不变。按住 Windows 键再按 A，不能误录成 A。
4. 只按修饰键、同时按两个普通键、长按普通键、先松开修饰键、先松开普通键；均符合录入规则。
5. `Tab`、`Shift + Tab` 正确切换焦点，不产生错误绑定；进入框时已按住的键全部松开后，可以正常录入。
6. 按住组合时点击其他字段、切换设置页、切换窗口或关闭设置；未完成的组合被丢弃，释放按键后应用快捷键恢复，无误触发或修饰键卡住。
7. 录入重复组合，页面提示两个冲突动作，保存被阻止；修改冲突字段后提示消失。
8. 保存后重新打开及重启，值一致；取消设置时不改变原配置。旧配置中的 `win+enter` 等仍可显示并原样保存。
9. 切换中英文，核对提示；在不同 DPI 下检查三个输入框和下方提示不重叠、不裁切。
10. 验证非美式键盘布局、Num Lock 状态及固件 Fn 转换。配置按 Windows 上报的虚拟键识别，符号标签采用美式名称；Fn 本身通常不独立上报。
11. `RegisterHotKey` 模式下使用被其他程序占用的组合，确认应用设置时显示注册失败，没有将录入成功当作生效成功。

以上历史版本曾允许额外修饰键。当前实现已改为完整组合键精确匹配：音频、Prompt 和 Menu 仅在主键与 Ctrl/Shift/Alt/Win 修饰键集合全部一致时触发，只有完整组合键重复才判冲突。`Ctrl+Q`、`Shift+Q`、`Alt+Q` 可分别绑定；未绑定的 `Ctrl+Shift+Q` 不触发这些操作。

本次回归覆盖同主键的全部 16 种修饰键集合、不同动作 ID 的独立派发、多按或少按修饰键不匹配、长按期间变更修饰键不重复派发，以及两个设置保存入口的同主键绑定与重复组合检查。Alt 菜单遮蔽、录入暂停、注入事件跳过和 RegisterHotKey 的 Rewrite 复制保护继续保留。实际 Windows 键盘操作仍需实机回测。

本次验证通过：工作区 439 项自动测试、`cargo fmt --all --check`、Linux 与 Windows 目标的全工作区 Clippy（`-D warnings`），以及启用静态 FFmpeg 的 Windows GUI／CLI 发布版编译和链接。

## 录入后恢复原值问题的回归

用户反馈 Audio Hotkeys、Menu key 和 Prompt Hotkey 都能进入录入提示，但按下单键或组合键后立即恢复原值。三者共用的录入器已作以下调整：

- 进入焦点时不再等待聚合修饰键或没有扫描码映射的虚拟状态；对于实际已释放但未收到松键事件的初始按键，录入时重新核对状态，避免一直等待。
- 等待期间保留录入提示；尚未确认的内容不写入设置草稿。
- 在键盘钩子内按事件顺序更新录入状态，再向输入框发送带代次标记的预览、确认、无效或等待结果。异步按键状态只用于核对进入焦点时的等待，已经开始录入的组合仍由实际按下和松开事件维护。

新增核心测试覆盖漏收初始松键后录入单键及全部八种 Ctrl/Shift/Alt 组合、等待期间的重复按键与真实按住的键，以及系统异步状态不能清除正在录入的组合。新增 Windows 原生测试覆盖消息中的按键和修饰键保真、必填及可选输入框的预览和松开确认、等待提示与过期消息丢弃。

本次通过 470 项工作区测试、格式检查、Linux 和 Windows GNU 目标的全工作区全目标 Clippy（`-D warnings`），以及启用静态 libav 的 Windows GUI／CLI 发布版编译和链接。

此前的原生输入框测试仅做了 Windows 目标交叉编译；本轮兼容环境执行结果见下文。Linux 运行的核心测试和 Windows 交叉编译不替代实机键盘验证。实机回归还应包含鼠标进入、Tab/Shift+Tab 切换、按住组合时切换窗口，以及两个全局快捷键后端。

## 再次反馈后的捕获会话修正

用户复测仍报告按键时短暂刷新，随后立即恢复旧值。此前的等待状态修改未解决用户环境中的实际故障。

本轮修正：

- 设置窗口和 Prompt 编辑器在快捷键输入框已经聚焦时自行处理激活通知并返回零，保留子控件焦点；阻止 `DefWindowProc(WM_ACTIVATE)` 把焦点移到顶层窗口、触发 `WM_KILLFOCUS`，继而取消录入并恢复旧值。
- 同一输入框重复收到窗口激活通知时保留当前会话及已按下的修饰键，防止重新初始化后丢弃组合。
- 旧输入框的失焦消息只结束自己的会话；设置窗口或 Prompt 编辑器的停用／销毁通知只结束属于自身的捕获，避免取消另一窗口已经开始的录入。
- 捕获范围依据系统前台输入队列的实际焦点判断，不再要求控件根窗口与前台顶层句柄直接相等。
- 再次点击已经聚焦的录入框时重装钩子，供新一轮录入使用。
- 已保存的 Hotkey debug 开关启用 `[capture]` 日志，记录会话启动、钩子事件、注入标记、预览／确认／无效结果、失焦及取消。每个会话最多 32 条钩子事件和 64 条控件记录，窗口切走后的具体按键不记录。

新增 Win32 回归测试 `duplicate_activation_and_previous_fields_cannot_cancel_current_chord`，验证修饰键按下后重复激活仍保留组合，旧控件失焦和其他窗口的停用不会取消当前录入。

交互测试 `foreground_capture_with_runtime_hotkeys` 标记为 ignored，需要交互桌面和外部键盘输入。它可以使用普通父窗口，也可以在 `DICTATE_CAPTURE_FULL_SETTINGS=1` 时打开完整 Settings，进入 Audio Hotkeys 页，在收到 Ctrl 的预览后补发 `WM_ACTIVATE`，检查焦点仍在输入框，再确认 `Ctrl+Alt+K` 录入成功且同组合的全局动作计数仍为零。`DICTATE_CAPTURE_BACKEND=register` 选择 RegisterHotKey，否则使用低级钩子。

本轮使用 Wine 10、Xvfb 和 XTest 键盘输入执行了上述 Win32 程序。完整设置页的激活回归在修复前的两个后端均失败：焦点回到顶层窗口，显示恢复为原来的 `Ctrl + Alt + Q`，与用户描述的闪回路径一致。修复后，同一测试的调试版和优化发布版在两个后端均保留输入框焦点并确认 `Ctrl+Alt+K`，全局动作计数为零；三个非交互 Win32 回归测试也通过。

通过 473 项 Linux 工作区测试、格式和差异检查、Linux／Windows GNU 目标全工作区全目标 Clippy（`-D warnings`），以及启用静态 libav 的 Windows GUI 发布版编译和链接。GUI 安装包重新生成，并以可执行文件哈希后缀另存一份，便于辨别此次修复版本。

该结果属于兼容环境验证，用户 Windows 上的自然输入序列仍需实机复测；若仍出现，可从 Debug 页的 `[capture]` 记录区分无效组合、焦点取消或钩子交付失败。
