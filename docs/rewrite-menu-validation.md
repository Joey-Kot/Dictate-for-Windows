# Rewrite 菜单验收记录

本记录将自动检查、Windows 功能验收和四组视觉验收分开。四张参考图仍是菜单材质和布局的设计标准，不是程序运行截图；内置图标改用用户随后提供的 25 个双色 SVG。用户首次报告菜单打开后选区变灰、复制超时以及菜单过大，触发键为 `Alt+A`，开启 Hook；修复后用户已确认功能测试没有问题。此结论限于用户实际测试的场景，未确认下方完整矩阵全部通过。Windows 版本尚未确认。

此前对比截图 `codex-clipboard-764c4ebf-9cdf-4995-868d-14bf7d211d0a.png` 右侧的实际菜单呈平灰不透明表面，旧 DWM 材质路径未通过视觉验收。更换为 Accent 材质后，用户已提供深色截图 `codex-clipboard-d9f37b80-7171-49a9-879e-e7d4112d549a.png` 和浅色截图 `codex-clipboard-13343f0b-7e3b-49c0-a9e6-233012837d5e.png`，认可当前深色效果，并要求把浅色底色不透明度从 80% 调至约 70% 试用。此次认可限于所提供的深色场景，不表示四组矩阵全部通过。Windows 10 实机验收由用户完成，编译成功不能替代这些验收。

## 首次实机反馈后的修正

- 选区失去输入焦点是此次 `Ctrl+C` 超时的前置问题。保留现有复制等待、剪贴板事务和 Rewrite 输入规则，修正菜单与热键的焦点副作用。
- Hook 原先吞掉 `Alt+A` 的 A，却让目标应用收到孤立的 Alt 按下与松开。现在首次拦截主键时，若 Alt 按下且 Ctrl 未按下，在执行动作前注入一组未分配键 `VK_E8` 按下与松开，避免目标应用进入菜单栏模式；保留真实 Alt 松开、长按过滤及注入事件跳过处理。机制依据见 [AutoHotkey 官方说明](https://raw.githubusercontent.com/AutoHotkey/AutoHotkeyDocs/v2/docs/lib/A_MenuMaskKey.htm)和[微软虚拟键表](https://learn.microsoft.com/en-us/windows/win32/inputdev/virtual-key-codes)。注入失败记入 Hotkey 调试日志。
- 菜单显示、隐藏与定位统一使用显式 `SWP_NOACTIVATE | SWP_NOOWNERZORDER`。关闭已隐藏的菜单不再重复调用 `ShowWindow(SW_HIDE)`；后者的公开语义包含激活另一窗口，见 [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)。不记录并恢复目标窗口。
- 首次缩放后宽度为 280 DIP，行高 40 DIP、图标 22 DIP、字号 14 DIP、上下留白各 4 DIP。最新对比后进一步把宽度改为 248 DIP，其余保持，七行菜单为 248×288 DIP。文字与图标按原生 DPI 绘制，滚动条绘制和命中使用同一组参数。
- 用户已报告 `Alt+A` + Hook 修复后的功能测试通过。本轮材质调整不修改激活或焦点处理代码。下方保留两种后端、多应用、滚轮和拖动等逐项回归要求，不将用户的整体反馈扩展为每项均已实测。

## 本轮材质修正与验证边界

- 关闭原先的 `DWMSBT_TRANSIENTWINDOW`，设置为 `DWMSBT_NONE`；`DwmExtendFrameIntoClientArea` 的四边扩展量改为零，保留 DWM 的 8 DIP 圆角和外部阴影，避免完整客户区的平灰底层盖住背景。
- 在独立的兼容模块中动态解析 `user32.dll` 的 `SetWindowCompositionAttribute`，使用 `WCA_ACCENT_POLICY=19`、Acrylic 状态 `4`、flags `0`。`GradientColor` 只提供单层底色：浅色 `#F7F7F7` 的 alpha 为 `0xB3`，不透明度约 70%；深色 `#202227` 保持 `0xCC`，不透明度 80%。上轮调整仅改变浅色底色不透明度，底色、尺寸和交互保持不变。Direct2D 不再叠加整块底色，只在材质失败时绘制实色回退；文字、图标及交互细节仍单独绘制。
- 仅在 Windows 11 圆角属性可用、桌面合成启用且允许透明效果时尝试。Windows 10、透明关闭、高对比度、节电模式或接口不可用/调用失败仍使用配色一致的实色回退。
- Accent 策略没有稳定公开契约，不能把动态调用成功当作视觉通过。微软对 [SetWindowCompositionAttribute](https://learn.microsoft.com/en-us/windows/win32/dwm/setwindowcompositionattribute) 的说明要求动态解析该入口，并建议优先使用 `DwmSetWindowAttribute`；本次把兼容调用隔离并保留失败回退。旧路径的失活实色问题与微软 [Acrylic 材质说明](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic) 中的失活行为一致，但具体机器上旧问题的原因仍不能仅凭截图确定。

Accent 深色无滚动条场景已有实机截图和用户认可。浅色无滚动条截图为调整前 80% 底色的效果，约 70% 底色效果待用户反馈；其余场景仍按下方记录保留，未将两张截图扩展为完整视觉矩阵通过。

## 内置图标替换与验收范围

内置图库使用用户提供的 25 个双色 SVG，嵌入程序，深浅主题均保留 `#1E88E5` 和 `#64B5F6`，按图形边界归一化后等比居中显示。Default 使用 `chat` 双气泡图形，保留图标数据无效、资源缺失或损坏时的通用回退。

本轮仅使用按实际图形命名的 25 个 ID：`chat`、`messages`、`translate`、`eye`、`feather`、`document`、`shield`、`pie_chart`、`tags`、`text_card`、`box`、`flask`、`globe`、`cookie`、`window`、`plug`、`settings`、`layers`、`key`、`network`、`hierarchy`、`bar_chart`、`microphone`、`fingerprint`、`layout`。不提供旧图标 ID 迁移或别名。

编辑器显示紧凑的图标预览和名称，选择图标、导入图片两个按钮相邻。点击选择图标展开 5×5 浮层，仅展示 25 个图标，选中后关闭。方向键移动焦点，Tab/Shift+Tab 顺序移动并在首尾边界离开，Enter/空格选择，Esc 关闭且不选择。点击外部、编辑器失活、滚动和 DPI 变化均关闭浮层；正文滚动和固定保存/取消区域继续保留。

自定义图片导入、配置引用和回退机制保持不变。菜单仍使用浅色约 70%、深色 80% 的底色不透明度。本轮图标命名和紧凑浮层选择器尚未在 Windows 实机验收；已有功能和背景材质反馈，以及下方的历史截图，不代表当前图库或选择器的验收通过。

`dist/prompt-icons-preview.png` 来自程序实际使用的 `IconCache` 解码、缩放与缓存路径；更新后可用于核对当前图库的图形、颜色与居中效果。该 PNG 是运行图库渲染代码生成的预览，不是 Windows 菜单或选择器实机截图。

## 实现与自动检查范围

### 快捷键清空修复

用户报告 Menu key 的 Clear 背景错误、Edit prompt 的 Clear 文字未居中，以及清空提示词快捷键后保存崩溃。本轮让两个 Clear 按钮复用 Edit/Delete 的动作按钮绘制并居中文字：主设置按钮此前误走侧栏备用背景，编辑器按钮此前沿用字段按钮的左对齐与留白。

提示词空快捷键原本就允许保存。排查列表重绘时发现，空快捷键会让 `draw_text_line` 将空缓冲区指针传入 `DrawTextW`；单行和换行文本 helper 现均在文本为空时直接返回，避免该危险调用路径。尚无崩溃转储，不能据此认定用户机器上的最终根因已经确认，仍需用修复构建回测。

新增 `settings/text_tests.rs` 的一项 Windows 专属回归覆盖实际清空、校验、保存、重新加载以及 GDI 空文本绘制，已通过 Windows 目标的 `cargo check --tests` 和 Clippy 编译检查。`cargo test -p dictate-gui --target x86_64-pc-windows-gnu --features native-gui --no-run` 也已成功生成可运行的测试 EXE；这里只完成编译和链接，未在 Windows 上执行测试。25 个图标及 5×5 浮层保持不变，问题截图中的旧图标不作为本轮图标规格。

### 菜单与图标检查

菜单采用独立的 Win32 非激活窗口，使用 Direct2D、DirectWrite 绘制前景。配置默认关闭菜单，保留原提示词快捷键；空快捷键不注册，动作按稳定 Prompt ID 关联。图标支持默认、25 个内置双色 SVG 和应用管理的自定义图片。设置保存保留两级草稿及热键回滚流程。

自动检查覆盖范围：

| 范围 | 核对内容 |
|---|---|
| 配置 | 旧配置缺少菜单与图标字段；新增字段往返；非法图标引用回退；Prompt ID 不因编辑、排序改变 |
| 快捷键 | 空值与非空值混排；音频、提示词、启用菜单之间仅拒绝完整组合键重复，同主键不同修饰键独立触发；关闭菜单保留但不注册 key；两种后端的复制保护；CLI 不注册菜单；Alt 组合键遮蔽、两种释放顺序、长按过滤、Ctrl+Alt/AltGr 和录入重置 |
| 保存 | 提示词编辑期间允许菜单 key 暂空；主设置拒绝启用但无 key；更换热键失败、配置写入失败及回滚失败 |
| 布局 | 0、1、6、7、8 和大量条目；完整行高度；滚动上下限、滑块及命中位置；负坐标工作区；不同 DPI |
| 图标 | PNG/JPEG/SVG 解码；宽高比与透明度；畸形或过大输入；外部 SVG 资源；取消与保存失败；原文件移动、缓存及缺失资源回退 |

## Windows 功能验收（用户报告通过，完整矩阵待逐项记录）

每次记录 Windows 版本与 Build、显卡驱动、显示器布局、各屏 DPI、默认应用主题、透明效果、是否开启“悬停时滚动非活动窗口”、热键后端和目标应用版本。

### 不依赖配置的原生菜单打样

在 Windows 上运行独立预览入口：

```powershell
.\Dictate.exe --rewrite-menu-preview=6
.\Dictate.exe --rewrite-menu-preview=10
```

分别测试六项和十项；两次运行各切换系统默认应用深浅模式，得到四种基准场景。`F8` 在当前鼠标位置展开或关闭菜单，`F9` 退出。参数省略数量时默认六项，接受 `0`～`1000`；零项用于检查空菜单不显示。预览使用当前内置图标示例，不启动 Rewrite 请求，不读写应用配置。

预览诊断写入 `%TEMP%\dictate-menu-preview.log`，记录数量、展开、选择、前台窗口及焦点控件句柄、菜单栏模式和请求的材质或回退路径，不记录选中文本。即使前台窗口不变，焦点控件或菜单栏模式变化也会单独记录。该日志可辅助定位焦点转移，但不自动证明选区保持或背景模糊成立。记录 Accent 请求成功后，仍须在窗口不激活的状态下检查实际表面。

### 原生材质与交互门槛

1. 先使用至少六项的菜单，分别在亮色网页、暗色编辑器和复杂桌面背景上展开。核对菜单后方内容真实透出并模糊，文字和图标清晰，边缘没有矩形黑框、额外背景板或锯齿。
2. 展开前在目标应用选中文字。使用系统前台窗口检查或可见选区确认菜单从显示到关闭始终不激活；点击、滚轮和拖动不能让选区消失。不能通过激活菜单来换取模糊。
3. 在菜单保持非激活时确认材质仍然存在。微软说明 Background Acrylic 可能在窗口失活时转为实色，因此接口调用成功和截图中单纯半透明均不足以证明通过。见 [Acrylic 材质说明](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)。
4. Windows 11 圆角属性可用时检查新的 Accent Acrylic 路径，确认 `DWMSBT_TRANSIENTWINDOW` 已关闭、没有整块 Direct2D 底色叠加。Windows 10、透明关闭、高对比度、节电模式或接口失败时单独检查实色回退。本轮不再以公开 DWM transient 背景接口及其 Build 22621 门槛作为材质启用条件。
5. 关闭系统透明效果，或在材质不可用的环境中检查配色一致的实色回退。回退通过不等于正常支持环境的毛玻璃视觉通过。

当前圆角采用 8 DIP，与系统 DWM 圆角对齐，避免自绘表面与系统材质的轮廓不同而露出角部底层。用户给出的 12 DIP 是打样起点，最终仍需对照四张参考图确认轮廓比例和实际观感。

### 输入与 Rewrite

| 操作 | 预期 |
|---|---|
| 记事本、浏览器文本框、VS Code、Word 选中文字后打开菜单 | 原应用继续获得键盘焦点，选区保持 |
| 点击一个提示词 | 先关闭菜单、清理输入监听与捕获，再按该 ID 开始现有 Rewrite；只产生一个请求 |
| 请求期间切换输入框或选区 | 成功结果写入返回时的位置；不恢复原窗口或原选区 |
| 忙碌期间重复触发菜单或提示词 | 遵循现有互斥规则，不并发、不排队 |
| 再按 Menu key 或长按该键 | 再按关闭；长按不连续开关 |
| 按 `Esc` | 关闭菜单，原应用选区不被额外取消，主程序不退出 |
| 点击菜单外 | 关闭菜单，原点击继续到达目标应用 |
| 鼠标在菜单内滚动 | 只滚动菜单，后方软件不滚动；分别测试非活动窗口滚动开、关 |
| 拖动滑块后移出菜单再释放 | 拖动正确结束，后续鼠标不被残留捕获 |
| 关闭菜单、退出或销毁窗口 | 临时监听和鼠标捕获清理完整 |
| 没有提示词时触发 | 不出现空面板，现有状态区域提供提示 |

以上逐项在 `HOTKEY_HOOK=true` 与 `false` 下执行。输入读取继续遵循 Copy 行为；“无选区时插入”仅描述输出时的位置，不能据此跳过 Rewrite 的输入读取规则。

### 配置、图标与布局

1. 从旧配置启动，确认现有快捷键有效，菜单关闭，旧提示词显示默认图标。
2. 新建、编辑、删除和排序提示词；混合空快捷键与非空快捷键，确认快捷键与菜单均执行正确 ID。
3. 刚启用菜单但未填写 Menu key 时打开并保存提示词；编辑器允许保存，主设置最终保存拒绝缺少菜单 key。禁用菜单时 key 置灰但原值保留；该键不再被应用占用。
4. 在主设置和提示词编辑器分别录入与音频、其他提示词、Menu key 冲突的键，检查提示一致。清空可选 key，长按录入、取消录入及切换焦点均不误触发应用动作。
5. 使用被其他程序占用的快捷键、不可写配置目录和不可写图标目录，验证失败不会破坏旧配置、旧热键或旧图标；回滚失败应有可见错误。
6. 分别导入带透明通道的 PNG、JPEG、宽图、竖图和 SVG；图片居中且不变形，原色不随主题反转。文件损坏、引用丢失或格式无效时其他提示词仍能加载并显示默认图标。
7. 导入后取消编辑器；保存编辑器后取消主设置；导入后主设置保存失败；正常保存后重启并移动原图片。确认只有提交成功的引用生效，旧图标仍可使用。
8. 测试 0、1、6、7、8、几十个条目与长标题。1～7 项按实际数量完整显示，正常工作区超过七项只显示七个完整条目；标题单行省略，滚动条不盖住内容，不预留空白行。
9. 在 100%、125%、150%、200% DPI 与混合 DPI 多屏中，分别从左上、右下及负坐标显示器打开菜单，检查任务栏工作区限位、物理尺寸、文字锐度和点击位置。另测工作区不足七行的极端情形并记录处理结果。
10. 菜单打开期间切换默认应用深浅模式，检查背景、文字、边框、分隔线、悬停、按下和滚动条同步刷新。五种界面的设置与编辑器文案检查应同时覆盖 Tab 顺序、正文滚动和固定保存/取消区域。

## 四组视觉验收（深色已有用户认可，浅色继续调整）
